# Agent Spec: F-35 Fleet Sustainment Agent (`f35-sustainment-agent`)

> **Architectural Guardrail (Mandatory):** Agent Gateway is **NOT** used. The solution runs directly on **Agent Runtime** in `europe-west1` and uses a dedicated Google Cloud Service Account (`f35-sustainment-runtime-sa@antig-dave.iam.gserviceaccount.com`) to authenticate tools, BigQuery, and Discovery Engine APIs.

## Overview
The **F-35 Fleet Sustainment Agent (`f35-sustainment-agent`)** is a multi-agent ADK 2.0 sustainment system designed for Google Cloud's **Agent Platform** (**Gemini Enterprise Search and Conversation**, **Agent Runtime**, and **Agent Registry**). Agent Gateway is strictly omitted; tool execution and data access are authenticated directly via Agent Runtime and a dedicated Service Account.

All GCP services reside strictly in **EU** (`eu` multi-region for Gemini Enterprise & Discovery Engine, `EU` multi-region for BigQuery) and all compute/runtime infrastructure is deployed to **`europe-west1` (Belgium)** in GCP project `antig-dave` (`284046449012`).

It compresses fifth-generation F-35 Lightning II maintenance, logistics, and airworthiness workflows from days to minutes by coordinating four specialized domain sub-agents:
0. **UC0 / 0.1 / 0.5 Sub-Agent — `f35_maintenance_data_agent` (`@F35-Maintenance-Data`)**: Translates natural-language maintenance logbook, PHM/BIT fault event, and work-center tooling/SQEP queries into read-only BigQuery Standard SQL (`SELECT` and multi-table `JOIN`s) against Tables 7, 8, and 9 (`maintenance_work_orders`, `phm_bit_fault_events`, and `work_center_tooling_and_sqep` in `ukd_f35_sustainment_demo`, `location="EU"`, 100 records per table across all 9 warehouse tables), returning an Excel / Google Sheets-like Spreadsheet Card with Column Letters (`A`..`Z`), Status/Severity/Calibration Badges, Formula Summary Footer Rows (`=COUNTA()`, `=SUM()`, `=AVERAGE()`), and an automatic clickable `.CSV` download link (`https://storage.cloud.google.com/antig-dave-f35-staging-europe-west1/exports/...`).
1. **UC1 Sub-Agent — `f35_analytics_agent` (`@F35-Sustainment-Analytics`)**: Queries partition-pruned BigQuery tables in `EU` (`airframe_component_telemetry`, `global_depot_inventory`, `squadron_sortie_schedule` in `ukd_f35_sustainment_demo`), generates inline Vega-Lite bar/line chart specifications alongside Markdown tables, triggers automated depot replenishment alerts, and recommends tail-swap sortie reallocations.
2. **UC2 Sub-Agent — `f35_jtd_search_agent` (`@F35-JTD-Search`)**: Performs single-pass dense semantic retrieval (`pageSize=15`, `snippetSpec` only) across S1000D JTD manuals (`ukd-f35-jtd-ietm-ds`) and 5-year multi-service narrative logs (`ukd-f35-narrative-logs-ds`) hosted in `eu` (`eu-discoveryengine.googleapis.com`), normalizing UK/US maintenance terminology (`RAF`, `RN`, `USAF`, `USMC`) and anchoring every claim with verbatim `[Title](URI)` citations.
3. **UC3 Sub-Agent — `f35_airworthiness_orchestrator` (`@F35-Airworthiness-Agent`)**: Executes a parallel ADK 2.0 diagnostic fan-out combining 200 Hz MIL-STD-1553 flight-bus synchronization, deterministic Rainflow & Palmgren-Miner structural fatigue math (`MIL-HDBK-516C` / `DEF STAN 00-970`), multimodal ultrasonic C-scan defect extraction (`DOC-06`) joined against 3D CAD hole coordinates (`DOC-05`), and global mBOM fastener lot auditing (`Lot #8841-B`), staging a MIL-STD-3001 Structural Appraisal Report and draft Aircraft Form 700 / AFTO Form 781 behind a mandatory **Human-in-the-Loop (HITL)** engineering review gate.

## Architecture & Sub-Agents
- **Deployment & Data Residency**:
  - **GCP Project**: `antig-dave` (`284046449012`)
  - **Runtime & Compute Region**: `europe-west1` (Belgium) for Agent Runtime, Agent Registry, Cloud Build, and Artifact Registry.
  - **Data & Search Residency**: `EU` multi-region for BigQuery (`ukd_f35_sustainment_demo`), `europe-west1` for GCS buckets, and `eu` multi-region (`locations/eu`) for Gemini Enterprise and Discovery Engine datastores.
- **Runtime Multi-Agent Topology**:
  - **`root_agent` (`f35_sustainment_coordinator`)**: Root `LlmAgent` wrapped in `App(name="app", root_agent=root_agent, resumability_config=ResumabilityConfig(is_resumable=True), context_cache_config=ContextCacheConfig(min_tokens=2048, ttl_seconds=1800, cache_intervals=10))`. Routes incoming prompts across four strictly separated specialist sub-agents (`sub_agents=[f35_maintenance_data_agent, f35_analytics_agent, f35_jtd_search_agent, f35_airworthiness_orchestrator]`):
    - **`f35_maintenance_data_agent`**: Dedicated to UC0 conversational Text-to-SQL over `maintenance_work_orders`, Excel / Google Sheets Card rendering, and automatic GCS `.csv` export (`app/sub_agents/uc0_maintenance_agent.py`).
    - **`f35_analytics_agent`**: Dedicated to UC1 structured BigQuery telemetry, inventory, sortie scheduling, and Vega-Lite chart generation (`app/sub_agents/uc1_analytics_agent.py`).
    - **`f35_jtd_search_agent`**: Dedicated to UC2 unstructured Discovery Engine (`eu`) JTD/FRACAS semantic retrieval and cross-service jargon translation (`app/sub_agents/uc2_search_agent.py`).
    - **`f35_airworthiness_orchestrator`**: Dedicated to UC3 parallel ASIP diagnostics, deterministic physics, multimodal C-scan CAD mapping, mBOM lot audit, and HITL Form 700 release (`app/sub_agents/uc3_airworthiness_agent.py`).
- **Development Multi-Agent Orchestration (Three-Phase Build Workflow)**:
  - **Phase 1 (Plan)**: Single orchestrator designs the architecture and presents the complete plan for user approval (no subagent delegation during planning).
  - **Phase 2 (Build)**: Independent subagents work in parallel on isolated directories/worktrees (`Backend Implementer` on `/packages/api` & `app/`, `Frontend Implementer` on `/packages/web`, `QA / Test Agent` on `/tests`). No two subagents edit the same file simultaneously.
  - **Phase 3 (Integration)**: Orchestrator validates the combined code, runs unit tests and `agents-cli eval`, and merges branches.

### Use Case 3: Dynamic Flight Envelope Exceedance & HITL Airworthiness Recertification (`f35_airworthiness_orchestrator`)

    2. Runs deterministic Rainflow & Palmgren-Miner solver ($D_i = 0.0042$), returning **`104.2%` of Design Yield Strength**, triggering mandatory **`CLASS_A_ULTRASONIC_C_SCAN`** per **`JTD Rule 53-11-00`** (`DOC-04`).
    3. Extracts C-scan (`DOC-06`) bounding coordinates and joins with 3D CAD (`DOC-05` SRM Chapter 51-40) to isolate **`0.012`-inch shear elongation on Fastener Hole `#14`**.
    4. Audits mBOM (`MBOM-ZM151-F496-H14`): **Titanium `Ti-6Al-4V`, `Lot #8841-B`** (`312.0` hrs since install, **`0.015`-inch** maximum allowable limit). Since `0.012 in < 0.015 in`, teardown is not required; mandates calibrated torque-recheck per **`JTD Task Card 53-11-00-280`** and flags **`14` other global F-35 tails** carrying `Lot #8841-B`.

- **Input (Turn 2 — Human-in-the-Loop Engineering Approval)**: *"I am the Lead Stress Engineer. I have verified the deterministic Miner's Rule output and C-scan overlay for package AWR-700-20261102-ZM151. Confirm and sign off the Form 700 airworthiness release."*
- **Expected Output (Turn 2)**:
  - Calls `confirm_form700_hitl_release`, updating `hitl_review_status` to **`CONFIRMED_BY_ENGINEER`** under **`MIL-HDBK-516C / DEF STAN 00-970 / MIL-STD-3001`** and displaying operational execution telemetry.

## Tools Required (Human-Friendly & Readable Tool Definitions)

All tools must expose descriptive, human-readable function names, display titles, and clear natural-language docstrings so that human operators and Gemini Enterprise users understand tool operations and data provenance:

2. **`recommend_tail_swap_and_replenishment`** (Display: *Recommend Tail Swap & Depot Replenishment* | `f35_analytics_agent`):

3. **`render_sustainment_chart`** (Display: *Render Sustainment Chart & Presentation Slides* | `f35_analytics_agent`):
   - Dynamically renders high-resolution Full HD 16:9 widescreen PNG charts on the fly in memory (~300–450 ms) using headless Matplotlib (`Agg` backend at 160 DPI).
   - Automatically uploads the rendered PNG bytes to Google Cloud Storage (`gs://antig-dave-f35-staging-europe-west1/charts/<chart_name>.png`) and returns an authenticated HTTPS browser download link (`[📥 Download 16:9 Executive Slide Graphic (PNG)](https://storage.cloud.google.com/antig-dave-f35-staging-europe-west1/charts/...)`) for direct insertion into executive briefings, in addition to inline Vega-Lite v5 JSON specifications for Gemini Enterprise Canvas.

6. **`calculate_structural_fatigue_and_yield`** (Display: *Calculate Structural Fatigue & Yield Strength* | `f35_airworthiness_orchestrator` Task B):
   - Deterministic Python solver executing Rainflow cycle counting, Palmgren-Miner cumulative damage ($D = \sum n_i / N_i$), and yield strength percentage calculation under `MIL-HDBK-516C` and `DEF STAN 00-970`.
7. **`inspect_ultrasonic_cscan_and_map_cad`** (Display: *Inspect NDI Ultrasonic C-Scan & Map CAD Coordinates* | `f35_airworthiness_orchestrator` Task C):

9. **`assess_airframe_airworthiness`** (Display: *Assess Airframe Airworthiness (Parallel Diagnostic)* | `f35_airworthiness_orchestrator` Composite Tool):

10. **`generate_form700_airworthiness_package`** (Display: *Generate Form 700 Airworthiness Package* | `f35_airworthiness_orchestrator` Task E):

## Constraints & Safety Rules
1. **EU / `europe-west1` Regional Residency**: All GCP infrastructure (Agent Runtime, Cloud Build, Artifact Registry, Agent Registry) MUST deploy to `europe-west1` (Belgium), with BigQuery in `EU` and Discovery Engine / Gemini Enterprise in `eu`.
2. **Multi-Agent Domain Separation**: Do not allow a single agent to handle multiple domains—both during the 3-Phase Build Workflow (`Backend Implementer`, `Frontend Implementer`, `QA / Test Agent` in isolated worktrees) and at runtime (`root_agent` delegating to `f35_maintenance_data_agent`, `f35_analytics_agent`, `f35_jtd_search_agent`, and `f35_airworthiness_orchestrator`).
3. **MIL-HDBK-516C & DEF STAN 00-970 Deterministic Boundary**: The LLM must never compute or approximate Rainflow cycles, Palmgren-Miner cumulative damage ($D = \sum n_i / N_i$), yield load percentages, or 3D CAD coordinates. All numerical stress and elongation figures must originate from `run_asip_miners_rule_engine` and `extract_ndi_defect_and_map_cad`.
4. **Mandatory Human-in-the-Loop (HITL) Gate**: `confirm_form700_hitl_release` is blocked by `before_tool_callback` (`enforce_hitl_airworthiness_gate`) unless `generate_form700_airworthiness_package` was completed in an earlier turn and the user explicitly confirms engineering release.
5. **Zero Uncited Technical Claims**: Every JTD tolerance, torque value (`N·m`), or material temperature limit (`220°C` RAM degradation in `DOC-09`) must include an inline `[Doc ID: Title](URI)` citation.
6. **ADK 2.0 Latency & Platform Guardrails**:
   - No `gcloud` CLI subprocess invocations inside tools.
   - `enterprise=True` and `location="global"` on `Gemini` model initializations; string enum `thinking_level` (`"LOW"` / `"MEDIUM"` / `"HIGH"`) instead of integer `thinking_budget`.
   - `App(name="app", ...)` must match the `app/` package directory.
